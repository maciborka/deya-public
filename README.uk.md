# Deya — моніторинг і розумний заряд для гібридного інвертора Deye

[English](README.md) · **Українська**

Самостійно розгорнутий вебсервіс для **трифазного гібридного інвертора Deye** (розроблявся на 12 кВт LV-моделі,
SUN-*-SG0xLP3), підключеного через **WiFi-логер Solarman (LSW3)**. Він збирає телеметрію в локальній мережі,
прогнозує вироблення сонячних панелей і щовечора вирішує, до якого рівня зарядити АКБ від мережі за дешевим нічним
тарифом, щоб наступного дня якомога більше жити від сонця.

## Можливості

- **Збирач телеметрії** — протокол Solarman V5 (`pysolarmanv5`), один власник з'єднання, опитування кожні 10 с,
  повний знімок налаштувань кожні 5 хв. Дані зберігаються в PostgreSQL.
- **Дашборд** (FastAPI + чистий JS, без CDN): схема потоків енергії наживо, прогноз АКБ на 24 год, історія,
  діаграма Санкі добових потоків, графік «чим живився дім», журнал відключень світла, погода (Open-Meteo),
  графік «Сонце: прогноз і факт» по годинах. Світла/темна тема, UA/EN.
- **Прогноз сонця** від кількох сервісів (Open-Meteo, Forecast.Solar, Solcast) для кожної групи панелей.
- **Планувальник нічного заряду** — моделює сценарії сонця (від гіршого до кращого) × споживання і вибирає
  найменший нічний рівень заряду, за якого ймовірність купувати електрику вдень нижча за заданий рівень ризику.
  Правило похмурого дня: якщо сонця завтра очікується менше порогу, АКБ заряджається до стелі. Коректно працює
  при переході на літній/зимовий час.
- **Керування інвертором (за бажанням)** — записує слоти TOU (графік за часом доби), регістри 148–159 / 166–177,
  через чергу з білим списком регістрів, перевіркою застарілих значень, обмеженням частоти та контрольним
  зчитуванням. Режими: вимкнено / порадник / авто.
- **Адмінка Django** — тарифи (зони і ціни), групи панелей, сервіси прогнозу та їхні API-ключі, налаштування
  стратегії, ручна нічна ціль, журнал записів.
- Необов'язковий зовнішній доступ через **Cloudflare Tunnel**; дашборд захищено HTTP Basic auth.

## Архітектура

```
Логер Solarman ──TCP 8899──> deya (FastAPI: збирач, планувальник прогнозів, планувальник заряду, API, дашборд) :8000
                                │
                                └──> PostgreSQL <── admin (адмінка Django, володіє схемою/міграціями) :8001
```

- `app/` — сервіс FastAPI: `collector.py`, `decoder.py`, `forecast/`, `planner/`, `planner_service.py`,
  `inverter_writer.py`, `static/` (дашборд).
- `admin/` — проєкт Django; схема бази даних описана в `admin/core/models.py`.
- `tools/probe.py` — зонд лише для читання, зберігає регістри інвертора в `data/`.
- `tests/` — тести pytest (тести БД/API запускаються, коли `DEYA_TEST_DATABASE_URL` вказує на базу з `test` у назві).

## Швидкий старт

Потрібно: Docker з Compose і комп'ютер у тій самій локальній мережі, що й логер.

```bash
cp .env.example .env
# відредагуйте .env: IP і серійний номер логера, згенеруйте паролі/ключі:
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
# без Cloudflare Tunnel задайте COMPOSE_PROFILES= (порожнє)
docker compose up -d --build
docker compose exec admin python manage.py createsuperuser
```

- Дашборд: http://localhost:8000 (користувач/пароль `DEYA_WEB_USER` / `DEYA_WEB_PASSWORD`)
- Адмінка: http://127.0.0.1:8001/admin/ — додайте групи панелей (кВт піку, нахил, азимут, координати), тариф
  і сервіси прогнозу.

Серійний номер логера надруковано на його наліпці й показано в його вебінтерфейсі. Спершу перевірте зв'язок:
`python3 tools/probe.py --ip <ip-логера> --serial <серійник-логера>` (`pip install -r tools/requirements.txt`).

## Тести

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
docker compose exec admin python manage.py test core
```

## Безпека

Запис в інвертор **за замовчуванням вимкнено** (`control_mode = off`, `writes_enabled = false`).
Неправильні налаштування TOU можуть розрядити АКБ або зупинити заряд. Звірте карту регістрів для своєї моделі,
почніть з режиму «порадник» і порівняйте поради з реальністю, перш ніж вмикати автоматичний запис. Використовуєте
на власний ризик.

Ніколи не комітьте `.env`: там секрети бази даних, Django, дашборда й тунелю. API-ключі сервісів прогнозу
зберігаються в базі даних (адмінка), а не в репозиторії.
